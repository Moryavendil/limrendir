# Limrendir


## What is it ?

Limrendir allows to view and save a video stream from a Genicam compatible camera using the [Aravis library](https://aravisproject.github.io/aravis/). 
It is a mashup between Aravis Viewer, which allows for user-friendly interactions with a camera including control and stream visualisation, and [gevCapture](https://gitlab.com/gevcapture/gevcapture), which allows for user-unfriendly recording of said stream.


## Features

* See the livestream of any Genicam camera
* Record snapshots, or videos in different formats
* Change the field of view of the camera and the recorded region of interest easily and precisely
* Exposure and focus aids (zebra stripes, focus peaking), and an image metrics panel (histogram, camera alignment, Fourier transform)
* More to come!


## How to install

### 1. GStreamer plugins

Limrendir displays and records the video using GStreamer:

    sudo apt install gstreamer1.0-plugins-base gstreamer1.0-plugins-good gstreamer1.0-plugins-ugly \
                     gstreamer1.0-plugins-bad gstreamer1.0-libav gstreamer1.0-gtk3

### 2. Aravis (version >= 0.8)

#### Via `apt` (Debian/Ubuntu)

On recent distributions (e.g. Debian 13), the packaged Aravis is recent enough:

    sudo apt install libaravis-dev aravis-tools
    
#### Installing Aravis from source

If you need a recent version of Aravis, start by downloading the latest stable [release](https://github.com/AravisProject/aravis/releases)

```
wget https://github.com/AravisProject/aravis/archive/refs/tags/0.8.36.tar.gz -O aravis-0.8.36.tar.gz
tar -xzf aravis-0.8.36.tar.gz
cd aravis-0.8.36
```

And then follow the [official instructions](https://aravisproject.github.io/aravis/aravis-stable/building.html). 

Finally, refresh the list of installed libraries (otherwise limrendir fails to start with "error while loading shared libraries: libaravis..."):

    sudo ldconfig

### 3. Limrendir

Install the dependencies:

    sudo apt install cmake libgtk-3-dev libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev libusb-1.0-0-dev

Download this project and compile it:

    git clone https://github.com/Moryavendil/limrendir.git
    cd limrendir
    cmake -B build && cmake --build build
    ./build/limrendir

(Everything generated by the compilation goes in the `build` folder, which can be deleted at any time.)

Use option `--help` to know about the available options.

#### Launching limrendir with a click

    ./install-launcher.sh --desktop

Limrendir then appears in the applications (from there, right click on it to pin it to the dock) and on the desktop (without `--desktop`, only in the applications). A terminal opens next to it to show its messages; use `--no-terminal` to remove it. It also creates `~/.local/bin/limrendir`, so that typing `limrendir` in any terminal runs it (if `~/.local/bin` was not in your `PATH`, open a new terminal or log in again). Run the script again after moving the limrendir folder. `./uninstall-launcher.sh` removes the launchers and the command.

## How to use

### Recording a video

Choose the format in the recording settings, then press the record button or the space bar. Three formats are available:

* **mp4** (lossy): compressed (H.264), small files read by every video player.
* **mkv** (lossless): compressed without loss (FFV1) of the image as displayed (8 bits per color), larger files.
* **gcv** (lossless): the frames exactly as the camera sends them, with the camera timestamp of each frame: the most precise for timing, very large files.

mp4 and mkv videos are played at 30 fps, whatever the recording frame rate. They are rotated and flipped like the displayed video (as are the snapshots), which is written in their metadata (`imageTransform`, the regions being given in camera image coordinates); gcv files hold the frames as the camera sends them, never rotated nor flipped.

The rotation and flips are kept while the same camera is used (crop, zoom, recordings, back to the camera list and to the video), and reset when another camera is chosen.

### Exposure and focus aids: zebra stripes and focus peaking

* **Zebra stripes** (key `w`, or the striped button of the image bar): moving red diagonal stripes over the saturated pixels (8-bit value of at least 253, 12-bit value of at least 4063).
* **Focus peaking** (key `p`, or the button next to it): the sharp edges are shown in yellow, which helps to focus. Each press cycles through off / low / medium / high sensitivity. Each level is meant for a contrast of the edges, and shows them only close to the best focus: low for contrasted edges (black / white, the most precise focusing), medium for ordinary ones, high for faint ones. A level meant for fainter edges shows the contrasted ones over a larger range of focus: when the edges show too early, lower the sensitivity.

The current state is shown at the right of the status bar. Both are drawn over the displayed video only: snapshots and recordings are not affected. They work during recordings too (updated less often, to leave the computer to the recording), and never slow down the acquisition: when the computer is busy, they are simply updated less often.

They are available for the Mono8 and Mono12 (Mono12, Mono12p, Mono12Packed) pixel formats only.

### Image metrics: histogram, alignment, Fourier transform

Press `t` (or the bar chart button of the image bar) to show a panel on the right of the video. The window is widened to make room for it, so that the video keeps its size (except when the window is maximized or fullscreen). The metrics are computed on the ROI when it is shown (key `r`), on the whole image otherwise. Each section can be collapsed, and is then not computed:

* **Histogram**: 256 bins from black to full scale, whatever the bit depth (blue: black pixels, red: saturated pixels, yellow line: mean), on a linear or logarithmic scale, with the minimum, maximum, mean, standard deviation, 1st and 99th percentiles, and the fractions of saturated and black pixels, in the units of the camera.
* **Alignment**: the angle of the nearly vertical lines (walls, light sheets...) and of the nearly horizontal ones (a free surface...), or of both for a grid, as seen on the screen, from -45 to 45 degrees, to about 0.01 degree (the eye cannot do better than about 1 degree). The gauge is green when the lines are within 0.05 degree of the screen axes, orange within 0.5 degree. While the image does not move, the measurement is averaged over the frames (a few seconds), so that the noise of the camera does not make it fluctuate; as soon as the camera is turned, the average starts again. The angles are found from the whole region: straight lines that cross most of it give the best precision.
* **Fourier transform**: log power spectrum of the region, binned to 2^n x 2^m with at most 256 x 256 bins (Hann window, zero frequency at the center), turned like the video.

The vertical scale of the histogram only changes when the highest bar becomes twice higher or lower, at most once per second, so that it does not jump with the noise.

The metrics are computed a few times per second (once per second during recordings) by the same low priority thread as the zebra stripes, without slowing down the acquisition. They are available for all the mono formats, the 8-bit Bayer formats (raw values, colors mixed) and RGB8 / BGR8 (luma).

Press `h` in the video to print all the key bindings (they are also listed in the keyboard help button). The keys are not shortcuts while a value is typed in a field (exposure, frame rate...): press Return or Escape, or click anywhere else, to leave the field.

### Trying limrendir without a camera

Using the option `--fake-camera` creates a simpler fake camera inside limrendir.

## Troubleshooting

### Camera not listed

To see the cameras available to aravis, use `arv-tool`. If it does not show your camera, try running it as an administrator.

#### USB Cameras

If `arv-tool` only finds your camera when ran as administrator, it is a problem of USB authorizations. You can solve this by creating a new udev rule, i.e. an `aravis.rules` file in the `/etc/udev/rules.d` directory (see [here](https://aravisproject.github.io/aravis/aravis-stable/usb.html#permissions)).

One-liner for Debian/Ubuntu:

    echo 'SUBSYSTEM=="usb", ATTRS{bDeviceClass}=="ef", ATTRS{bDeviceSubClass}=="02", ATTRS{bDeviceProtocol}=="01", ENV{ID_USB_INTERFACES}=="*:ef0500:*", MODE="0666"' | sudo tee /etc/udev/rules.d/aravis.rules

#### Ethernet cameras

* Check that the camera is powered, whether directly or using Power-over-Ethernet injector (normal PC Ethernet ports provides no power to the camera).
* heck that the connection is suitable. In GNOME network manager, 
	- In the Identity tab, set MTU to 9000.
	- In the IPv4 tab, choose Link-Local Only.
	- In the IPv6 tab, choose Disable, then click Apply.

Then disconnect and reconnect the cable.

The result of `ip link` corresponding to the ethernet port (you can check which it is using `nmcli device`) should show `state UP`. If it says `NO-CARRIER`, the cable is the issue.

### Missing frames

During recording there can be dropped frames, i.e. frames that were not saved for one reason or another and that are missing in the video. These are especially frequent when having a high data rate (around and above 100 MB/s), a slow computer and/or several programs running in parallel. Limrendir should indicate that a frame was dropped by displaying "(X)" in a warning message. If you are experiencing dropped frames, you may try the following:

#### Check the camera-computer connection
* Ensure that the camera is properly connected to your computer with an appropriate cable (Ethernet: a category 6 Ethernet cable / USB: a USB 3.0 cable).

#### Check the Ethernet settings (Ethernet cameras)
* Check that the connection MTU is high enough. Go to network manager, select the network connection, check that MTU >= 8192 (e.g. 9000).
* If the dropped frames comes from timeouts being reached (usually indicated by the ARV_BUFFER_STATUS_TIMEOUT buffer state), try using higher packet timeout and frame retention time: launch limrendir with arguments `-m 1000 -p 1000`

#### Check the USB memory limit (USB3 cameras)
* USB cameras: Check that the USB buffer limit is high enough (display it with `cat /sys/module/usbcore/parameters/usbfs_memory_mb`).

To raise the USB memory limit until next reboot: 

```echo 1000 | sudo tee /sys/module/usbcore/parameters/usbfs_memory_mb```

To raise the USB memory limit permanently: 
add usbcore.usbfs_memory_mb=1000 to the kernel command line.
On Debian/Ubuntu with GRUB, add it inside the quotes of `GRUB_CMDLINE_LINUX_DEFAULT` in the file `/etc/default/grub`, for example with:

```
sudo sed -i 's/^GRUB_CMDLINE_LINUX_DEFAULT="\(.*\)"/GRUB_CMDLINE_LINUX_DEFAULT="\1 usbcore.usbfs_memory_mb=1000"/' /etc/default/grub
sudo update-grub
```

#### Upgrade the permissions given to limrendir
* Run limrendir as administrator (using `sudo`), which will allow to make the Aravis thread realtime, and to give the recording thread the highest priority (limrendir sets the priority of its acquisition threads itself, as much as it is allowed to).
* For Ethernet cameras, use packet sockets: `sudo setcap cap_net_raw+ep build/limrendir`
* Raise the priority of the whole program: `sudo nice -n -5 ./build/limrendir`

#### Limit other usages of CPU resources
 * If your computer is a 2000's toaster with less than 2 GB of RAM, try buying another one
 * Limitate usage of CPU-heavy and RAM-guzzling applications such as Chrome

See also the advices [here](https://aravisproject.github.io/aravis/aravis-stable/usb.html) for USB cameras and [here](https://aravisproject.github.io/aravis/aravis-stable/ethernet.html) for Ethernet cameras.

## About the code

Limrendir is written in C and based on Aravis (0.8/0.10), gstreamer (1.0) and GTK+ (3.0).

A consequent part of the code is directly burrowed or adapted from Aravis Viewer. My additions consist mainly of 

 * Smoother control of the acquisition and field of view parameters with key bindings routines inspired by gevCapture and
 * Recording capabilities, with different formats supported.

I am not a professional software developer so the code quality might not be perfect. But hey, it works !


## Technical information

* Use option `log-level`to set the debug level (2=info (default), 3=debug, 4=trace)
* The logs of each session are saved in `~/.local/state/limrendir/logs/` (the path is shown at startup).
* Some choices are remembered between sessions in `~/.local/state/limrendir/settings`: the folder and format of the last saved snapshot, the folder of the last saved video and the recording format.
* If another vendor's camera software is installed (e.g. Basler pylon, which sets `GENICAM_GENTL64_PATH`), aravis also sees USB3 cameras through that software's GenTL driver, so `arv-tool` lists them twice. Limrendir only lists the entry of aravis' own USB3 Vision driver; launch it with `--allow-duplicates` to also list the other one.
* During a recording, the video is written in a temporary file named `<name>.recording.<format>`, in the folder of the last saved video: after a crash, the recording can be found there.
